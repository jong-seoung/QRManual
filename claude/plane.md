# plane — QRManual 디자인·요구 양식

> 이 프로젝트의 디자인·콘텐츠 *구체값*을 채워넣는 양식.
> [`design.md`](./design.md)는 *원칙·구조*, 이 파일은 *값* — 책임이 다르다.
> 빈 칸은 결정이 안 된 항목. 결정 시점에 채우고 §10 변경 이력에 한 줄.

---

## 0. 메타

| 항목 | 값 |
| --- | --- |
| 프로젝트명 | QRManual |
| 한 줄 정의 | _(예: QR 스캔으로 제품 매뉴얼·정보를 즉시 보여주는 웹 서비스)_ |
| 주요 사용자 | _(예: 1) 매뉴얼을 스캔해 보는 일반 사용자, 2) 매뉴얼·QR을 등록·관리하는 관리자)_ |
| 시작일 | _(YYYY-MM-DD)_ |

## 1. 무드 / 톤

원하는 인상을 키워드로. 충돌하면 *우선순위*를 매긴다.

| 항목 | 값 |
| --- | --- |
| 키워드 1순위 | _(예: 신뢰, 명확, 모던)_ |
| 키워드 2순위 | _(예: 친근, 미니멀)_ |
| 피해야 할 톤 | _(예: 너무 화려, 과한 그라데이션)_ |
| 레퍼런스 사이트 | _(URL 1~3개)_ |
| 회피 사이트 | _(있다면 URL — "이런 느낌 싫다")_ |

## 사용 절차

1. 디자인 결정 미팅에서 §1~§9 채움. 비어 있는 칸은 제안하고 컨펌.
2. 변경 시 §10 변경 이력에 한 줄.
3. `design.md`의 디자인 토큰(Tailwind v4 `@theme` 또는 `tailwind.config.ts`)은 이 파일의 §2·§3·§4 값을 기반으로 채움.
4. **이 파일의 값이 코드보다 권위 있다** — 코드와 다르면 코드를 고친다.
