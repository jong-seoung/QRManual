# design — UI/UX 단일 출처

UI 원칙, 디자인 토큰 *구조*, 컴포넌트 라이브러리 선택을 한 파일에 통합.
`architecture/`(예정)가 "어떻게 동작하는가"라면, 이 파일은 "어떻게 보이고 어떻게 쓰이는가"를 다룬다.

> **책임 분담**:
> - **이 파일(`design.md`)** = *원칙·구조·디폴트 패턴*. 색상 헥스 같은 구체값은 들어가지 않음.
> - **[`plane.md`](./plane.md)** = *이 프로젝트의 구체값* — 무드, 메인색상, 서브색상, 타이포 등.
>
> 즉 이 파일은 "어떤 *구조*로 디자인 결정이 들어가야 하는가"를 정의하고, 실제 *값*은 `plane.md`에서 결정된다.

> 한 파일이 비대해지면 그때 `design/` 폴더로 승격해 분리한다 (지금은 YAGNI).

---

## 1. UI 원칙

핵심 5~7개로 압축. 결정 시 충돌하면 위에서부터 우선.

1. **데스크탑 기준** — 컴포넌트와 페이지의 우선 형상은 데스크탑(`lg` 1024px+)에서 결정한다. 작은 화면은 그 형상을 *축약·조정*하는 방향으로 단계적으로 좁혀가며 검증. Tailwind 디폴트가 모바일 우선이라는 점은 유지하되, 설계 출발점은 데스크탑이다.
2. **반응형 기본** — 모든 페이지·컴포넌트는 처음부터 반응형. 단일 breakpoint 전용 화면 금지. 정당화 가능한 예외만 ADR로 기록.
3. **즉시 가독** — QR 스캔 후 첫 화면에서 *무엇에 대한 매뉴얼인지* 1초 내 파악되어야 한다. 큰 헤딩 + 1~2개 핵심 액션 + 그 외는 접거나 아래로.
4. **접근성 우선** — 키보드 내비/스크린 리더 기본 지원. 터치 타겟 최소 44×44px. 매뉴얼 본문은 WCAG AA 대비.
5. **일관성** — 같은 의미는 같은 컴포넌트로.
6. **다크 모드** — 처음부터 토큰으로 분리 (light/dark 변수 동시 정의). 야간/현장 사용 가능성 고려.
7. **즉시 피드백** — 사용자 액션마다 0.1초 내 반응. 매뉴얼 로딩은 스켈레톤.

## 2. 디자인 토큰 (구조만 — 값은 `plane.md`에서)

Tailwind v4의 `@theme` 또는 `tailwind.config.ts`의 `theme`에 매핑된다. **이 섹션은 *어떤 토큰 슬롯이 존재해야 하는가*를 정의하고, 각 슬롯의 헥스/폰트명 같은 *값은 [`plane.md`](./plane.md)에서 결정*된다.**

- **Breakpoint** — Tailwind 기본 그대로 (변경 거의 없음)
  - `sm` 640px (큰 모바일 / 작은 태블릿)
  - `md` 768px (태블릿)
  - `lg` 1024px (작은 데스크톱)
  - `xl` 1280px (일반 데스크톱)
  - `2xl` 1536px (와이드 모니터)
  - 모바일 디폴트는 ~640px 미만. **320px 폭에서도 깨지지 않게 검증**.
- **색상 팔레트** (슬롯) — primary / secondary / accent / neutral / semantic(success/warning/error/info)
  - 각 슬롯의 light/dark 헥스 값 → `plane.md` §2
- **타이포 스케일** (구조) — display / heading-{1..3} / body / caption. 반응형은 `text-base md:text-lg` 기본
  - 폰트 패밀리·크기 단위 → `plane.md` §3
- **간격** — 4px 기준 8단계 (디폴트)
- **둥글기** — sm/md/lg/full. 디폴트값(보통 `md`) → `plane.md` §4
- **그림자** — sm/md/lg + focus ring. 강도 디폴트 → `plane.md` §4
- **모션** — duration 토큰 (fast 150ms / base 250ms / slow 400ms). 강도 디폴트 → `plane.md` §4

## 3. 컴포넌트 라이브러리

**기본 채택 후보**: shadcn/ui (Radix 기반, 코드 복사형 — 락인 없음)
**대안 검토**: Mantine, Chakra UI (도입 시 ADR 필수)

선택 기준:
- 코드 소유권 — 우리 저장소에 들어와야 커스터마이징 자유
- a11y — Radix 기반이면 키보드/스크린 리더 검증됨
- Tailwind 친화 — 토큰 시스템과 잘 맞물림

**QRManual 도메인 특화 컴포넌트** (자체 구현):
- `QRCodeRenderer` — QR 코드 생성·표시
- `ManualSection` — 접기/펼치기 가능한 매뉴얼 섹션
- `ProductHeader` — 매뉴얼 진입 시 상품 정보 카드
- `LanguageSwitcher` — i18n 언어 전환 (모바일에서도 명확하게)

**반응형 의무**: shadcn/ui에서 가져왔든 자체 구현이든, 모든 컴포넌트는 §4의 3개 viewport(320 / 768 / 1280px)에서 깨지지 않게 검증. 통과 못하면 머지 금지.

## 4. 레이아웃 패턴 (반응형 기본)

### 앱 셸 (breakpoint별 변환)

| Breakpoint | 내비게이션 | 사이드바 | 메인 |
| --- | --- | --- | --- |
| 모바일 (~`md`) | 헤더 + 바텀 내비 (또는 햄버거 → 드로어) | 숨김 | 단일 컬럼, 풀폭 |
| 태블릿 (`md`~`lg`) | 헤더 | 토글 가능 (collapsed 기본) | 1~2 컬럼 |
| 데스크톱 (`lg`+) | 헤더 | 펼침 (사이드 고정) | 2~3 컬럼, max-width 컨테이너 |

### QRManual 핵심 페이지 패턴

- **매뉴얼 진입(/m/[id])** — 모바일 단일 컬럼. 상단: 상품 헤더, 본문: 섹션 목록, 하단: 관련 링크/문의
- **상품 목록(관리자)** — 모바일 카드형, 태블릿+ 테이블/그리드 (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3` 패턴)
- **상품 편집 폼** — 모바일 풀폭, 데스크톱 max-width 제한 (`max-w-xl` 또는 `max-w-2xl`)
- **QR 코드 발급** — 모바일 단일, 데스크톱 좌(폼) + 우(미리보기) (`lg:grid-cols-[1fr_300px]`)

### 공통 규칙

- 컨테이너 max-width — 본문 기본 `max-w-screen-xl mx-auto px-4 md:px-6 lg:px-8`
- 매뉴얼 본문은 가독성 위해 `max-w-prose`(약 65ch) 권장
- 터치 타겟 — 최소 44×44px (모바일에서 버튼/링크 검증)
- 가로 스크롤 — 표/코드블록만 허용, 그 외에는 절대 발생 안 하게 검증
- 빈 상태(empty state) — 모든 목록 페이지에 명시. 모바일에서도 가독성 확인.

### 검증 절차

새 페이지/컴포넌트 작성 시 최소 3개 폭에서 직접 확인:
- 320px (작은 모바일 — 갤럭시 폴드 외부 등)
- 768px (태블릿)
- 1280px (데스크톱)

Playwright e2e도 위 3개 viewport로 돌리는 것을 기본으로.

## 5. 접근성 체크리스트

- [ ] 모든 인터랙티브 요소가 키보드로 접근 가능

- [ ] 대비 — WCAG AA 4.5:1 이상 (텍스트), 3:1 (UI)
- [ ] 폼 — label-input 연결, 에러 메시지 명시적 연결 (`aria-describedby`)
- [ ] focus-visible 스타일 명시 (Tailwind `focus-visible:ring-2 ...`)
- [ ] 다국어 — `<html lang>` 동적 반영 (next-intl이 처리)
