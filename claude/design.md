# design — UI/UX 단일 출처

UI 원칙, 디자인 토큰 *구조*, 컴포넌트 라이브러리 선택을 한 파일에 통합.
`architecture/`(예정)가 "어떻게 동작하는가"라면, 이 파일은 "어떻게 보이고 어떻게 쓰이는가"를 다룬다.

> **책임 분담**:
> - **이 파일(`design.md`)** = *원칙·구조·디폴트 패턴*. 색상 헥스 같은 구체값은 들어가지 않음.
> - **[`plane.md`](./plane.md)** = *이 프로젝트의 구체값* — 무드, 메인색상, 서브색상, 타이포 등.
>
> 즉 이 파일은 "어떤 *구조*로 디자인 결정이 들어가야 하는가"를 정의하고, 실제 *값*은 `plane.md`에서 결정된다.

> 한 파일이 비대해지면 그때 `design/` 폴더로 승격해 분리한다 (지금은 YAGNI).

> **현재 스코프**: 데스크탑 기준 / 반응형 / 다크·라이트 모드 / 다국어. 모바일·태블릿 전용 최적화·터치 타겟·바텀 내비 등은 일단 도입하지 않는다.

---

## 1. UI 원칙

결정 시 충돌하면 위에서부터 우선.

1. **데스크탑 기준** — 컴포넌트와 페이지의 우선 형상은 데스크탑(`lg` 1024px+)에서 결정한다. 좁은 화면에서 깨지지만 않으면 충분; 모바일 전용 최적화는 별도 결정이 있기 전까지 보류.
2. **반응형 기본** — 데스크탑 폭 내에서도 가변 폭에 안정적이도록 구성. 고정 픽셀 레이아웃 지양, max-width 컨테이너 + 가변 그리드/플렉스가 기본 패턴.
3. **다크·라이트 모드** — 처음부터 토큰으로 분리해 light/dark 변수를 동시에 정의. `globals.css`의 `:root` / `.dark`에서 토큰 오버라이드, 컴포넌트는 토큰만 참조. 두 세트가 갖춰지지 않은 색상은 도입하지 않는다.
4. **다국어** — 한·영 동시 지원을 전제로. 텍스트는 `next-intl` 메시지로 추출, 길이 변화(영어 약 1.2~1.5배)에서도 레이아웃이 깨지지 않게 컴포넌트 폭을 결정.

## 2. 디자인 토큰 (구조만 — 값은 `plane.md`에서)

Tailwind v4의 `@theme` 또는 `tailwind.config.ts`의 `theme`에 매핑된다. **이 섹션은 *어떤 토큰 슬롯이 존재해야 하는가*를 정의하고, 각 슬롯의 헥스/폰트명 같은 *값은 [`plane.md`](./plane.md)에서 결정*된다.**

- **Breakpoint** — Tailwind 기본 그대로 사용. 설계 기준은 `lg`(1024px) 이상.
  - `lg` 1024px (작은 데스크톱)
  - `xl` 1280px (일반 데스크톱)
  - `2xl` 1536px (와이드 모니터)
  - 그 아래(`sm`/`md`)는 *깨지지 않는 수준*만 보장. 본격 모바일 레이아웃은 도입 시 별도 결정.
- **색상 팔레트** (슬롯) — primary / secondary / accent / neutral / semantic(success/warning/error/info)
  - 각 슬롯의 **light/dark 헥스 값 둘 다** `plane.md` §2에서 결정. 한쪽만 있는 색상은 도입 금지.
- **타이포 스케일** (구조) — display / heading-{1..3} / body / caption.
  - 폰트 패밀리·크기 단위 → `plane.md` §3
- **간격** — 4px 기준 8단계 (디폴트)
- **둥글기** — sm/md/lg/full. 디폴트값(보통 `md`) → `plane.md` §4
- **그림자** — sm/md/lg + focus ring. 강도 디폴트 → `plane.md` §4
- **모션** — duration 토큰 (fast 150ms / base 250ms / slow 400ms). 강도 디폴트 → `plane.md` §4

## 3. 컴포넌트 라이브러리

**기본 채택 후보**: shadcn/ui (Radix 기반, 코드 복사형 — 락인 없음)
**대안 검토**: Mantine, Chakra UI (도입 시 ADR 필수)

선택 기준:
- 코드 소유권 — 우리 저장소에 들어와야 커스터마이징 자유
- a11y — Radix 기반이면 키보드/스크린 리더 검증됨
- Tailwind 친화 — 토큰 시스템과 잘 맞물림
- **다크 모드 토큰 매핑이 가능해야 한다** (§1.3)

**QRManual 도메인 특화 컴포넌트** (자체 구현):
- `QRCodeRenderer` — QR 코드 생성·표시
- `ManualSection` — 접기/펼치기 가능한 매뉴얼 섹션
- `ProductHeader` — 매뉴얼 진입 시 상품 정보 카드
- `LanguageSwitcher` — i18n 언어 전환 (헤더 영구 노출)
- `ThemeToggle` — 다크/라이트 토글 (헤더 영구 노출)

**검증 의무**: shadcn/ui에서 가져왔든 자체 구현이든, 모든 컴포넌트는 §4의 데스크탑 폭(1280px / 1024px) + 라이트·다크 두 모드 + 한·영 두 로케일에서 깨지지 않게 검증. 통과 못하면 머지 금지.

## 4. 레이아웃 패턴

### 앱 셸

데스크탑 기준 단일 형상.

| 영역 | 처리 |
| --- | --- |
| 헤더 | 좌측 로고/네비, 우측 `LanguageSwitcher` + `ThemeToggle` + 사용자 메뉴. sticky 상단. |
| 사이드바 | 필요 시 고정 펼침. 토글은 도입 시 별도 결정. |
| 메인 | max-width 컨테이너 (`max-w-screen-xl mx-auto`). 좌우 패딩은 페이지 외곽에서 제거됨(현 정책). |
| 본문 가독 영역 | 매뉴얼 본문은 `max-w-prose`(약 65ch) 권장. |

### QRManual 핵심 페이지 패턴

- **매뉴얼 진입(/p/[id])** — 단일 컬럼. 상단: 상품 헤더, 본문: 섹션 목록, 하단: 관련 링크/문의.
- **상품 목록(관리자)** — 그리드 카드 (`grid-cols-3 xl:grid-cols-4`).
- **상품 편집 폼** — `max-w-2xl` 중앙 정렬.
- **QR 코드 발급** — 좌(폼) + 우(미리보기) (`lg:grid-cols-[1fr_300px]`).

### 공통 규칙

- 가로 스크롤 — 표/코드블록만 허용, 그 외에는 절대 발생 안 하게 검증.
- 빈 상태(empty state) — 모든 목록 페이지에 명시.
- 다크 모드 — 토큰만 참조; 컴포넌트 내부에 하드코딩된 색상 금지.

### 검증 절차

새 페이지/컴포넌트 작성 시 최소 다음 조합에서 직접 확인:

- 1280px (일반 데스크톱) × 라이트 / 다크
- 1024px (작은 데스크톱) × 라이트 / 다크
- 두 로케일(`ko` / `en`)에서 텍스트 오버플로 없음

Playwright e2e도 위 2개 viewport × 2개 테마 × 2개 로케일을 기본으로.
